# Revue kimi — REQ-NOT-004 (messageries Telegram/Discord/Gotify/Pushover)

- **Commit revu** : `f9dd481` (PR #95, fusionnée)
- **Revue** : kimi, post-merge (mandat autonome), 2026-08-07
- **Corrections** : appliquées dans la PR NOT-006 (commit `fix(not): revue kimi NOT-004`)

## Findings et triage

| # | Sévérité | Verdict | Résolution |
|---|----------|---------|------------|
| F1 | MED | **Corrigé (partiellement, assumé)** | L'URL d'un webhook Discord embarque son jeton. `Debug` manuel redacté ajouté (`Discord`) — plus aucun secret possible dans les journaux. En revanche l'URL reste **visible via l'API/UI pour son propriétaire** : parité legacy (Wallos affiche l'URL), et c'est la donnée que l'utilisateur doit pouvoir relire/vérifier. Même statut que l'URL du webhook générique (elle aussi potentiellement porteuse de secret). |
| F2 | MED | **Corrigé** | Jeton Telegram interpolé dans le chemin de l'URL de l'API Bot sans encodage. Validation stricte du format à l'enregistrement (`telegram_bot_token_is_valid` : `<id numérique>:<[A-Za-z0-9_-]>`) → un jeton porteur de `/`, `?`, `#` ou espace est refusé (422). Tests unitaires + cas d'intégration. |
| F3 | HIGH | **Rejeté (faux positif) + test de régression** | Bypass SSRF allégué par zone ID IPv6 (`http://[fe80::1%25eth0]/`). Le parseur d'URL (whatwg, crate `url`) **rejette** ces hôtes : `webhook_url_is_safe` renvoie déjà `false`. Prouvé et figé par le test `ipv6_zone_identifiers_are_rejected`. |
| F4 | LOW | **Rejeté (documenté)** | `api_base` (telegram/pushover) lu de la DB sans validation. Posable **uniquement** par SQL direct (la validation API jette toute clé inconnue) : un attaquant qui écrit la config en DB contrôle déjà toutes les URLs de canaux (webhook incluses) — la validation à la relecture ne changerait pas la surface. Déjà documenté (ADR 0046). |
| F5 | MED | **Corrigé** | Un nom d'abonnement contenant `@everyone`/`@here` déclencherait une mention massive côté Discord. `"allowed_mentions": {"parse": []}` ajouté systématiquement au payload. (Divergence legacy assumée : Wallos est vulnérable à ce comportement.) |
| F6 | MED | **Corrigé** | Journal du cron sans diagnostic. Le warn porte désormais `code` + `http_status` issus de `diagnose_send_error` (introduit par NOT-006) — redacté par construction, jamais l'erreur brute. |
| F7 | LOW | **Corrigé** | `non_empty_string` acceptait les chaînes blanches. Trim + rejet du vide ; la valeur stockée est trimmée. Cas d'intégration ajouté. |
| F8 | LOW | **Corrigé** | `avatar_url` Discord non validée (un `javascript:`/`file:` était relayé). Validation de forme `is_http_url` (http/https analysable) → 422 sinon. |
| F9 | LOW | **Rejeté (parité)** | `{url}/message` doublerait `/message` si l'utilisateur le saisit. Comportement **identique au legacy** (`rtrim($url, '/') . "/message"`), et l'envoi de test (NOT-006) diagnostique immédiatement la config fautive (`http-status: 404`). |
| F10 | LOW | **Rejeté** | `list`/`delete` sans annotation NOT-004. Ce sont des opérations génériques de l'abstraction (NOT-005) ; la part NOT-004 (redaction des jetons en liste) est tracée sur `row_to_dto`, qui porte les trois exigences. Même schéma que NOT-003. |
