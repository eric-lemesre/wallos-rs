# Revue kimi — REQ-SEC-004 (chiffrement au repos des secrets de canaux)

- **Commit revu** : `feat(sec): REQ-SEC-004` (PR #104, fusionnée)
- **Revue** : kimi, post-merge (mandat autonome), 2026-08-07
- **Corrections** : `fix(sec): revue kimi SEC-004` (cette PR)

## Findings et triage

| # | Sévérité | Verdict | Résolution |
|---|----------|---------|------------|
| F1 | MED | **Rejeté (documenté)** | Dérivation SHA-256 sans sel ni itérations. Acceptable pour une clé machine aléatoire (simple expansion) ; la recommandation « 32+ octets aléatoires » est dans l'ADR 0053 et la doc du module. La stratégie « env var simple » est un choix **validé par Eric** — passer à Argon2id/HKDF serait une nouvelle décision, notée comme évolution possible (le préfixe `enc:v1:` versionne le schéma). |
| F2 | MED | **Corrigé** | AAD absent : un texte chiffré pouvait être rejoué d'un champ/canal/foyer vers un autre par un accès DB en écriture. `encrypt`/`decrypt` prennent désormais un AAD `(foyer, type de canal, champ)` (`channel_secret_aad`) : toute copie inter-contextes échoue à l'authentification GCM. Test dédié (3 axes de rejeu). Pas de souci de compat : aucune donnée réelle chiffrée sans AAD n'existe (fenêtre de 30 min entre les deux PRs, projet non déployé). |
| F3 | LOW | **Corrigé** | Une valeur d'entrée déjà préfixée `enc:v1:` aurait été re-chiffrée puis indéchiffrable. Refus explicite (422) à la création. |
| F4 | MED | **Corrigé** | Le déchiffrement via `/notifications/channels/{id}/test` n'était pas exercé (les tests NOT-006 écrasent la config par SQL). Test ajouté : canal chiffré intact (fusion jsonb pour `api_base`), `/test` → le récepteur reçoit le chemin Telegram avec le jeton **en clair**. |
| F5 | LOW | **Corrigé** | Échec de déchiffrement silencieux. `tracing::warn!` structuré (`channel_id`, `field`, `reason` ∈ {missing-key, decrypt-failed}) — jamais le secret, le chiffré ni la clé. |
| F6 | LOW | **Corrigé** | Comportement en cas de clé changée non testé. Test ajouté : création avec la clé A, cron avec la clé B → canal ignoré, zéro envoi (échec fermé prouvé). |
| F7 | LOW | **Rejeté** | `aes-gcm = "0.10"` jugé « ancien ». 0.10.x est la ligne **stable** actuelle de RustCrypto (0.11 est en pré-version) ; `cargo-deny`/audit surveillent les avis. |
