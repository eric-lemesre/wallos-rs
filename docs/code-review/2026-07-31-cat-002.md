### F1 — Canal de timing sur l'anti-énumération (HIGH)

**Constat.** `UserRepository::create_account` (`crates/storage/src/users.rs:72-124`) insère
le foyer, puis l'utilisateur, puis, **uniquement en cas de succès**, sème les 16
catégories par défaut avant de committer. Sur un e-mail déjà enregistré, l'insertion
`users` viole la contrainte d'unicité, la transaction est rollbackée et **aucun insert
`categories` n'est exécuté** (`crates/storage/src/users.rs:115-118`).

**Conséquence.** Bien que les deux chemins retournent le même `201 CREATED` vide
(`crates/server/src/accounts.rs:82`), leur temps d'exécution diffère :

- Chemin nominal : hash argon2id + `insert households` + `insert users` + **16 inserts
  `categories`** + `commit`.
- Chemin dupliqué : hash argon2id + `insert households` + `insert users` (échec) +
  `rollback`.

Le hash argon2id domine le temps, mais les 16 inserts ajoutent une durée DB non nulle et
relativement stable. REQ-AUT-001 critère 2 exige que « *la réponse est identique et aucune
information n'indique l'existence du compte* ». Un canal de timing est une information.
Un attaquant capable de répéter l'appel (surtout si REQ-AUT-008 n'est pas encore appliqué
ou contourné par un botnet) peut discriminer un compte existant d'un compte inexistant
par comparaison des temps de réponse.

**Options de traitement :**

- **A)** Documenter explicitement le risque résiduel dans REQ-AUT-001 / ADR 0023 et
  s'appuyer sur REQ-AUT-008 (rate-limit) pour rendre la mesure impraticable.
- **B)** Réduire le delta en effectuant un travail factice équivalent sur le chemin
  dupliqué (par exemple insérer les catégories dans une sous-transaction annulée, ou
  introduire un délai constant) — plus lourd et sujet à calibration.
- **C)** Inverser la logique : vérifier l'unicité **avant** le hash avec une requête
  constant-time, puis traiter les deux chemins de manière symétrique. Attention : une
  simple vérification préalable crée elle-même un canal de timing si elle n'est pas
  soigneusement calibrée.

**Recommandation agent :** option A en attendant une passe durcissement, **à condition**
que le rate-limit de REQ-AUT-008 soit déployé et que le risque soit mentionné dans
`docs/adr/0023-cat-002-default-categories-translated-seed.md` ou dans une note de
REQ-AUT-001. Sans cela, le finding reste HIGH.

### F2 — Traçabilité incomplète de `createAccount` (MEDIUM)

**Constat.** L'endpoint `createAccount` fait désormais trois choses :

1. Créer un compte (REQ-AUT-001) — déjà déclaré.
2. Valider et persister la langue choisie (REQ-I18N-001) — `crates/server/src/accounts.rs:60-70`.
3. Déclencher le semis des catégories par défaut traduites (REQ-CAT-002) — via
   `UserRepository::create_account(..., language)`.

Pourtant, l'annotation `utoipa` ne liste que `REQ-AUT-001`
(`crates/server/src/accounts.rs:35`) et la fonction ne porte que
`#[requirement(REQ-AUT-001)]` (`crates/server/src/accounts.rs:46`).

**Conséquence.** L'opération OpenAPI n'est pas traçable pour CAT-002 / I18N-001. Le macro
`#[requirement(...)]` du crate `req-macros` ne supporte qu'un seul identifiant, donc on
ne peut pas simplement étendre l'annotation existante. Il manque au moins :

- une fonction helper `resolve_registration_language` annotée `REQ-I18N-001` ;
- une mise à jour de l'extension `x-requirements` en
  `json!("x-requirements", ["REQ-AUT-001", "REQ-CAT-002", "REQ-I18N-001"])`.

Sans cela, `cargo xtask trace` et la matrice de traçabilité sous-estiment la couverture
API de ces deux exigences (risque TRC-05 / TRC-01 silencieux).

**Recommandation agent :** ajouter le helper I18N-001 et mettre à jour `x-requirements`.
Le seed en storage est déjà annoté `REQ-CAT-002` (`crates/storage/src/users.rs:223`),
donc la couverture storage/core est correcte.

### F3 — Test d'isolation §9 : commentaire périmé + assertion affaible (LOW)

**Constat.** `authz_other_list_categories` (`crates/server/tests/categories.rs:493-497`)
a un commentaire affirmer : « *sa liste est la sienne (vide ici)* ». Depuis le seed,
la liste de l'autre compte n'est **pas vide** : elle contient les 16 catégories par
défaut. L'assertion utilise `custom_categories`, qui filtre les défauts anglais, donc elle
ne vérifie que l'absence de la catégorie personnalisée d'Alice, pas la présence des
catégories par défaut de Bob.

**Conséquence.** Le test reste **correct** sur l'isolation inter-foyer, mais le commentaire
est faux et l'assertion est plus faible qu'elle ne le laisse entendre. Un changement
futur qui casserait le seed pour l'autre compte pourrait passer inaperçu.

**Recommandation agent :** corriger le commentaire et renforcer l'assertion, par exemple :

```rust
assert!(custom_categories(&pool, &other).await.is_empty());
assert_eq!(categories(&pool, &other).await.len(), DEFAULT_CATEGORY_COUNT);
```

### F4 — Test API anti-énumération ne vérifie pas les catégories (LOW)

**Constat.** `duplicate_email_is_indistinguishable`
(`crates/server/tests/accounts.rs:63-76`) vérifie que le second appel renvoie `201` et
que le nombre d'utilisateurs reste à 1. Il ne vérifie pas le nombre de catégories.

**Conséquence.** Un bug qui ferait que le chemin dupliqué sème quand même des catégories
(par exemple une mauvaise gestion de transaction dans `storage`) ne serait pas détecté
au niveau serveur. Le test storage `duplicate_email_seeds_no_categories`
(`crates/storage/tests/users.rs:109-131`) couvre le repository, mais pas l'endpoint HTTP.

**Recommandation agent :** ajouter une assertion sur `select count(*) from categories`
(ou via `GET /categories` authentifié après le second appel) pour vérifier qu'il n'y a
pas de catégories orphelines supplémentaires.

### F5 — Validation incomplète du jeu anglais (LOW)

**Constat.** `account_creation_without_language_seeds_english_defaults`
(`crates/storage/tests/users.rs:95-98`) vérifie que le nombre de catégories vaut
`DEFAULT_CATEGORY_COUNT`, qu'il contient "Music" et qu'aucun nom n'est français.

**Conséquence.** Ce test ne garantit pas que les 16 noms correspondent exactement au jeu
anglais attendu. Une corruption partielle (nom manquant/remplacé) passerait si "Music"
est présent et qu'aucun accent français n'est détecté.

**Recommandation agent :** comparer l'ensemble complet comme dans le test français
(`crates/storage/tests/users.rs:64-68`), avec un `BTreeSet`.

### F6 — Réponse `500` non documentée dans OpenAPI (LOW)

**Constat.** `create_account` (`crates/server/src/accounts.rs:72-86`) peut retourner `500`
en cas d'échec du hachage argon2id ou d'erreur DB (y compris lors du seed de 16
catégories). L'annotation `utoipa` ne liste que `201` et `422`
(`crates/server/src/accounts.rs:35-44`).

**Conséquence.** Le contrat OpenAPI est incomplet. AGENTS.md §6 impose que chaque réponse
d'erreur suit le schéma `Problem` et est documentée.

**Recommandation agent :** ajouter `(status = 500, description = "...", body = Problem,
content_type = "application/problem+json")` à l'annotation `utoipa`, ou traiter les
erreurs DB/hash comme une `500` documentée.

### F7 — Schéma `language` sans énumération (NIT)

**Constat.** Le champ `language` de `CreateAccountRequest`
(`crates/proto/src/lib.rs:95-100`) est typé `string | null` sans contrainte sur les
valeurs possibles.

**Conséquence.** Les consommateurs du contrat OpenAPI ne découvrent les codes supportés
(`en`, `fr`) que dans la description textuelle. La validation reste côté serveur (422),
mais le contrat est moins expressif.

**Recommandation agent :** ajouter une restriction `enum` côté `utoipa` si possible, ou
au minimum un `pattern`/`examples`.

### F8 — `custom_categories` suppose l'anglais pour tous les comptes (NIT)

**Constat.** Le helper `custom_categories`
(`crates/server/tests/categories.rs:121-130`) filtre les catégories par défaut en
utilisant systématiquement `Language::English`.

**Conséquence.** Si un test futur crée un compte avec `language: "fr"`, le helper
laissera passer les catégories par défaut françaises et les tests d'isolation/CRUD
pourraient échouer silencieusement ou devenir instables.

**Recommandation agent :** documenter l'invariant dans le commentaire du helper (tous les
comptes de test créés sans langue), ou rendre le helper paramétrique sur la langue.

### F9 — Seed en 16 requêtes individuelles (NIT)

**Constat.** `seed_default_categories` (`crates/storage/src/users.rs:229-236`) exécute
16 fois `insert into categories ...`.

**Conséquence.** 16 allers-retours DB dans une transaction au lieu d'un seul `INSERT ...
VALUES (...), (...)` ou d'un `UNNEST`. Sur un endpoint d'inscription, l'impact est faible
mais évitable.

**Recommandation agent :** batcher les inserts (par exemple avec `UNNEST` sur les tableaux
de noms/UUIDs) pour réduire le nombre de requêtes.

## Points vérifiés corrects

- **Atomicité** : `create_account` ouvre une transaction (`crates/storage/src/users.rs:82`),
  insère foyer + utilisateur + 16 catégories, puis committe. En cas de doublon, le
  rollback annule aussi le foyer (`crates/storage/tests/users.rs:153-158` confirme
  `household_count == 1`).
- **Isolation par foyer** : le seed utilise le `household_id` nouvellement créé
  (`crates/storage/src/users.rs:104-106`) et `CategoryRepository::list` filtre toujours
  par `household_id` (`crates/storage/src/categories.rs:104-111`). Aucune requête ne
  risque de lire les catégories d'un autre foyer.
- **Absence d'unwrap/expect/panic en production** : `cargo clippy -p wallos-core -p
  wallos-storage -p wallos-server --tests -- -D warnings` passe. Les seuls `unwrap`
  apparaissent dans les helpers de test (`#[cfg(test)]` ou fichiers `tests/`).
- **Validation `language` optionnel** : absent → `NULL` + seed anglais ; code supporté
  → persistance + seed traduit ; code non supporté → `422 language_unsupported`
  (`crates/server/src/accounts.rs:60-70`, `crates/server/tests/categories.rs:183-192`).
- **Adequation aux critères CAT-002** : tests core (cardinalité, doublons, traductions),
  storage (jeu FR complet, jeu EN par défaut, pas de seed sur doublon) et serveur
  (présence via `GET /categories`, 422 langue invalide).
- **Conformité ADR 0023 / fixture oracle** : la sentinelle "No category" est exclue, le
  jeu compte exactement 16 entrées, les traductions FR correspondent à la fixture
  `e2e/fixtures/oracles/REQ-CAT-002-default-categories.json`.

   (helper annoté + `x-requirements` mis à jour).

remettent pas en cause la sémantique. Les NIT F7-F9 sont de l'optimisation / expressivité.
