## 1. Correction du repli de diacritiques

### F1-HIGH — Ligatures, `ß`, `ø` et caractères hors latin non repliés

**Fichier** : `crates/core/src/text.rs:18-36`

Le repli est :

```rust
input
    .nfd()
    .filter(|c| !is_combining_diacritic(*c))
    .flat_map(char::to_lowercase)
    .collect()
```

avec `is_combining_diacritic` limité au bloc `U+0300..=U+036F`.

**Scénarios d'échec concrets :**

1. **Ligatures françaises** : `"œuvre".nfd()` produit `"œuvre"` (la ligature `œ`, U+0153, **n'a pas** de décomposition canonique en NFD). `fold_for_search("œuvre")` renvoie `"œuvre"`. Une recherche `"oeuvre"` ne trouvera pas `"œuvre"`.
   - Impact réel en français : `œuf`, `cœur`, `sœur`, `œuvre`.
2. **`ß` allemand** : `"Straße".nfd()` reste `"straße"` (le `ß`, U+00DF, ne se décompose pas en `"ss"` en NFD). Une recherche `"strasse"` échoue.
3. **`ø` danois/norvégien** : `"København".nfd()` reste `"københavn"`. Une recherche `"kobenhavn"` échoue.
4. **Casse turque** : le repli utilise `to_lowercase` standard. `"İstanbul"` (I pointée majuscule turque) devient `"istanbul"`, ce qui est correct, mais `"Istanbul"` (I majuscule non turc) devient aussi `"istanbul"`. Inversement, `"kedi"` cherché comme `"KEDI"` deviendra `"kedi"`, mais `"KEDI"` ne deviendra pas `"kedi"` si on s'attend à un traitement turc spécifique. Le commentaire du fichier indique le périmètre `en`/`fr` — cette limite est acceptable pour le périmètre ciblé, **mais** la ligature `œ` est un cas français réel.

**Recommandation** : étendre le repli pour décomposer explicitement les ligatures latines courantes (`œ` → `oe`, `æ` → `ae`) et documenter dans `text.rs` que `ß` et `ø` restent non repliés par design (périmètre en/fr). Alternativement, utiliser une bibliothèque de folding Unicode (`unicode-casefold`, `icu::CaseMapper`) si le périmètre s'élargit.

## 2. Tri : déterminisme, stabilité, placement des `None`

**Verdict sur cet axe : globalement correct.**

- `Sortable` porte `folded_name`, `amount_ref`, `next_due`, `id`.
- `sort_subscriptions` applique un départage systématique par `folded_name.then(id)` (lignes 381-384) : déterministe et stable.
- `none_last` place les `None` **en dernier** quel que soit le critère.
- Pour `Amount`, le code inverse explicitement la comparaison (`y.cmp(x)`) pour obtenir un ordre décroissant tout en gardant `None` en fin.

### F4-MEDIUM — Tests d'intégration du tri incomplets

**Fichier** : `crates/server/tests/subscriptions.rs:1039-1107`

Le test `sort_by_amount_normalizes_cycle_and_is_descending` crée trois abonnements en **EUR** avec des cycles différents. Il ne vérifie pas :

1. La **conversion de devise** : un abonnement en USD et un en EUR, triés par coût mensuel normalisé en devise de référence.
2. Le placement en fin des abonnements au coût **non calculable** (devise inconnue dans les données, ou taux manquant).
3. Le placement en fin des abonnements **sans échéance** pour `sort=next_due` (abonnement terminé ou hors plage).
4. Le **départage stable par `id`** en cas d'égalité parfaite du nom replié.

**Scénario d'échec potentiel** : si `monthly_in_reference` renvoyait `Some(0)` au lieu de `None` pour un taux manquant, le test actuel ne le détecterait pas. Actuellement le code renvoie `None` (via `convert` qui retourne `None` si pas de taux), ce qui est correct, mais non testé.

**Recommandation** : ajouter au moins un test avec deux devises et un test avec un abonnement au taux manquant placé en fin.

## 5. Chargement des taux à la demande

**Verdict sur cet axe : correct.**

```rust
let table = if amounts.is_empty() && criterion != SortCriterion::Amount {
    RateTable::new(Vec::new())
} else {
    load_rate_table(...).await
};
```

- Si aucun montant actif n'est à agréger **et** qu'on ne trie pas par montant, la table vide évite un aller-retour base.
- Si `sort=amount`, on charge les taux même si `amounts` est vide (cas où tous les abonnements visibles sont inactifs/terminés mais on veut quand même les trier par coût normalisé).

**Scénario de bord vérifié** : foyer avec 3 abonnements inactifs, `?sort=amount` → `amounts.is_empty() == true` mais `criterion == Amount`, donc on charge la table. C'est correct.

**Fichier** : `crates/proto/src/lib.rs:635-644`


Le backend effectue déjà un trim (`crates/server/src/subscriptions.rs:469`) :
