- **Corrections** : appliquées dans le commit `fix(not): revue kimi NOT-006` (PR NOT-002)

## Findings et triage

| # | Sévérité | Verdict | Résolution |
|---|----------|---------|------------|
| F1 | HIGH | **Corrigé** | Aucune limitation de taux : l'endpoint déclenchait des requêtes sortantes illimitées (amplificateur de spam, oracle de connectivité). Limite **5 tests / 5 min par foyer**, fenêtre glissante **persistante** (`notification_test_attempts`, migration 0024 — correcte multi-instance), `429` + `Retry-After`, sur le modèle REQ-AUT-008. La tentative est journalisée **avant** l'envoi (pas de dépassement par concurrence). Test dédié. |
| F2 | MED | **Corrigé** | Bouton « Tester » cliquable en rafale. État `testing` : bouton désactivé pendant l'appel. |
| F3 | MED | **Corrigé (partiellement, documenté)** | `diagnose_send_error` sans tests unitaires. Ajout des cas constructibles sans I/O (`UnexpectedStatus` → `http-status`, erreur générique → `send-failed`). `timeout`/`connection-failed` exigent de vraies erreurs `reqwest` et `smtp-failed` une vraie erreur `lettre` : couverts par les tests d'**intégration** (`connection-failed`, `smtp-failed`) ; `timeout` non testé (il faudrait un récepteur qui dort 10 s — coût disproportionné, assumé). |
| F4 | MED | **Corrigé** | Cas `smtp-failed` non exercé via l'endpoint. Test ajouté : canal e-mail vers `127.0.0.1:1` → `{ok: false, code: "smtp-failed"}`. |
| F5 | MED | **Corrigé** | `authz_other` ne prouvait pas l'absence d'envoi. Le test repointe le canal vers un récepteur local et vérifie `captured` vide après le 404. |
| F6 | MED | **Corrigé** | Chemin 422 (config stockée illisible) non couvert. Test ajouté : config corrompue par SQL (clé obligatoire supprimée) → 422. |
| F7 | LOW | **Corrigé** | `days_until: 5` codé en dur alors que `due` peut saturer. Désormais dérivé : `(due - as_of).num_days()`. |
| F8 | LOW | **Rejeté** | `code` en `String` plutôt qu'enum OpenAPI. Choix assumé : identifiant **ouvert** — un nouveau code de diagnostic (p. ex. pour NOT-007 réessai) ne doit pas casser le contrat ni les clients générés. Les valeurs sont documentées sur le champ ; l'UI a un repli `default`. |
| F9 | LOW | **Rejeté** | `id = String` dans l'annotation utoipa. Cohérent avec `deleteNotificationChannel` (même paramètre, même pattern dans tout le dépôt) ; un UUID illisible → 404, testé. |
| F10 | LOW | **Rejeté** | Erreur API (401/500) affichée comme `testFailed` générique. Repli honnête, cas marginal (session expirée) ; la distinction fine des erreurs transport relève du bandeau d'erreurs global, pas de cette carte. |
| F11 | LOW | **Corrigé** | L'assertion de non-fuite ne vérifiait que l'absence de `127.0.0.1`. Test ajouté : l'ensemble **exact** des clés de la réponse est `{ok, code, http_status}`. |
| F12 | LOW | **Rejeté** | `Utc::now()` dans le handler. `test_notification(as_of)` est déjà une fonction pure paramétrée ; le handler est le point d'injection d'horloge normal du dépôt (même pattern que le cron), et aucun test n'a besoin d'une date fixe ici. |
