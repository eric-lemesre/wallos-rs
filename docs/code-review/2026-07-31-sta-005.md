## Vérification par axe

### 1. Moteur `occurrences_in_range` (`crates/core/src/schedule.rs:71-98`)

- **Bornes incluses** : la doc et le code utilisent `[from, to]` inclusivement
  (`occ >= from`, arrêt sur `occ > upper`).
- **`MAX_STEPS`** : réutilise la constante existante (`100_000`) comme garde-fou.
- **`end_date = min(to, end_date)`** : `upper` est calculé exactement ainsi
  (`Some(end) if end < to => end`, `_ => to`).
- **Monotonie/break** : les occurrences sont strictement croissantes par
  construction ; dès que `occ > upper` la boucle s'arrête, et `occurrence`
  renvoyant `None` déclenche aussi un break.

### 2. Isolation §9 (`crates/server/src/schedule.rs:123-124`)

Le handler appelle `SubscriptionRepository::list(&actor, &filter)`. Le repository
ajoute systématiquement `where household_id = $1` (`crates/storage/src/subscriptions.rs:207`)
et le filtre `active = true` est injecté. Les trois tests d'autorisation
(owner/other/anon) sont présents dans `crates/server/tests/schedule.rs:310-351`.

### 3. Exclusion inactifs + terminés

- **Inactifs (SUB-008)** : `SubscriptionFilter { active: Some(true), ..Default::default() }`
  (`crates/server/src/schedule.rs:119-122`), testé dans
  `crates/server/tests/schedule.rs:271-289`.
- **Terminés (SUB-009)** : `occurrences_in_range` reçoit `row.end_date` et borne
  `upper = min(to, end_date)`, testé dans `crates/server/tests/schedule.rs:244-269`
  et unitairement `crates/core/src/schedule.rs:325-351`.

### 4. Argent décimale (R4)

`SubscriptionRow.amount` est `rust_decimal::Decimal`
(`crates/storage/src/subscriptions.rs:24`). Le DTO expose `amount: String`
(`crates/proto/src/lib.rs:230`) et le handler fait `row.amount.to_string()`
(`crates/server/src/schedule.rs:150`). Aucun `f32`/`f64`.

### 5. Absence d'unwrap/expect/panic hors tests

Aucun dans le code de production (handler + composant React). Les `unwrap`/
`expect` observés sont dans `#[cfg(test)]` ou dans les helpers de tests
(`crates/server/tests/schedule.rs`), conformément à R5.

### 6. Bornes de fenêtre

- `days == 0` ou `days > MAX_WINDOW_DAYS` (`366`) → 422
  (`crates/server/src/schedule.rs:102-104`, testé `crates/server/tests/schedule.rs:291-306`).
- `from` mal formé → 422 (`crates/server/src/schedule.rs:106-109`).
- `checked_add_days` overflow → 422 (`crates/server/src/schedule.rs:112-114`).

### 7. Tri déterministe

Le handler trie en mémoire par `date`, puis `name`, puis `subscription_id`
(`crates/server/src/schedule.rs:389-394`). Les dates sont au format `YYYY-MM-DD`,
donc l'ordre lexicographique coïncide avec l'ordre chronologique.

### 8. Adéquation tests / acceptance

  (`crates/core/src/schedule.rs:293-323`) et en test d'intégration

- Aucune occurrence après `end_date` : couvert unitairement et en intégration
  (`crates/core/src/schedule.rs:325-351`, `crates/server/tests/schedule.rs:244-269`).
- Inactifs exclus : couvert (`crates/server/tests/schedule.rs:271-289`).
