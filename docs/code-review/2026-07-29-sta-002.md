## Verdict global

## Traitement

- **F1 ⏳ DIFFÉRÉ (dette transverse §8.1-e2e).** Le point est **valide** et **transverse** : comme pour STA-001, tous les specs e2e instancient `new TargetDriver(page, baseURL)` directement ; `AppDriver` ne déclare pas `subscriptionYearlyCost`, et `LegacyDriver` n'implémente même pas `AppDriver` (seulement `Harness`). Rendre ce seul scénario rejouable contre `legacy` exigerait (a) d'ajouter `subscriptionYearlyCost` à `AppDriver`, (b) d'implémenter cette méthode dans `LegacyDriver` en scrutant le DOM réel de Wallos, et (c) un refactor d'injection uniforme à toute la suite. L'oracle STA-002 est par ailleurs **authentiquement capturé** en exécutant le PHP de l'image pinnée (`$totalCostPerYear = $totalCostPerMonth * 12`) ; la moitié « gel depuis legacy » du §8.1 est donc satisfaite hors navigateur. Consigné comme **passe transverse dédiée** dans `.hermes`.
- **F2 ⚠️ PRÉSENT dans le commit ciblé.** Le commit duplique le défaut de STA-001 dans `row_to_dto` : `Money::new(row.amount, currency).unwrap_or_else(|_| Money::zero(currency))` remplace un montant négatif corrompu par zéro pour `monthly_cost` **et** `yearly_cost`, alors que le commentaire affirme retomber sur le montant brut. La correction (visible dans l'arbre de travail actuel) consiste à gérer `Err(_)` par un fallback sur `row.amount.to_string()`. Ce défaut est en pratique inatteignable car la migration `0008` impose `check (amount >= 0)`, mais le code et le commentaire sont contradictoires.
- **F3 ⏳ À COMPLÉTER.** L'oracle est correct pour les 7 vecteurs EUR qu'il contient, mais il ne couvre pas les devises à 0 décimales (JPY), le cas `one-time` de Wallos (`cycle = 5` → `getPricePerMonth` retourne 0 → annuel 0), ni les valeurs à la frontière de l'arrondi bancaire half-to-even. Ces cas devraient être ajoutés pour que l'e2e et les tests unitaires discriminent réellement la fonction `yearly_cost_rounded`.

## Points positifs confirmés

### 1. `yearly_cost` / `yearly_cost_rounded` dans `core` — fidélité et arithmétique

- **Relation fidèle à Wallos 5.4.2.** `stats_calculations.php` calcule `$totalCostPerYear = $totalCostPerMonth * 12` après avoir agrégé les `getPricePerMonth($cycle, $frequency, $price)` ([source `includes/stats_calculations.php`](https://raw.githubusercontent.com/ellite/Wallos/v5.4.2/includes/stats_calculations.php)). Le code de `core` reproduit exactement cette relation : `yearly_cost` = `monthly_cost(...) * 12`.
- **Arithmétique `Decimal` exacte.** `Decimal::from(12)` est représentable sans perte ; aucun flottant n'est utilisé (R4). Les facteurs de `monthly_cost` (`30`, `4.35` via `Decimal::new(435, 2)`, `1`, `12`) sont également exacts.
- **Arrondi cohérent.** `yearly_cost_rounded` arrondit le **brut** `yearly_cost` au nombre de décimales de la devise (`round_to` / half-to-even, REQ-CUR-005/CUR-007). C'est la bonne façon de reproduire `formatPrice(...)` appliqué à un prix annuel calculé, et non `monthly_cost_rounded * 12` qui introduirait un double arrondi.

### 2. Exposition DTO proto + server — cohérence create / list

- **Création / mise à jour.** `SubscriptionDto::from_core_derived` appelle `from_core`, qui calcule `monthly_cost` et `yearly_cost` via `monthly_cost_rounded` et `yearly_cost_rounded`.
- **Lecture / liste.** `row_to_dto` dans `crates/server/src/subscriptions.rs` calcule les deux mêmes champs via les mêmes fonctions arrondies.
- **Résultat.** Les deux chemins exposent le même affichage ; pas de dérive create vs list. Le champ `yearly_cost` est correctement ajouté au schéma OpenAPI et au client TypeScript généré (`frontend/ui/src/api/schema.d.ts`).

### 3. Oracle `REQ-STA-002-yearly.json`

- Les 7 vecteurs correspondent aux valeurs attendues par `yearly_cost` et aux valeurs affichées `displayed_eur` (`yearly_cost_rounded` en EUR à 2 décimales).
- Le vecteur `year / 99.99` est particulièrement discriminant : mensuel brut `8.3325`, annuel brut `99.99`, affiché `99.99` — la relation ×12 est exacte sans perte d'arrondi.

## F1 — Le scénario e2e ne peut pas être exécuté contre l'application d'origine

### Description

Le scénario importe et instancie directement `TargetDriver` :

```ts
// e2e/specs/subscription-yearly-cost.spec.ts:6
import { TargetDriver } from "../drivers/TargetDriver";

// …
const app = new TargetDriver(page, baseURL!);
```

L'interface `AppDriver` ne déclare pas de méthode `subscriptionYearlyCost` :

```ts
// e2e/drivers/AppDriver.ts
export interface AppDriver {
  // …
  subscriptionMonthlyCost(name: string): Promise<string>; // absent aussi d'ailleurs
  // pas de subscriptionYearlyCost
}
```

Et `LegacyDriver` n'implémente pas `AppDriver` ; il ne dispose même pas de méthodes de création/lecture d'abonnements.

### Conséquences

1. **Protocole oracle non respecté.** Le §8.1 impose d'écrire le scénario contre `AppDriver`, de l'exécuter avec `TARGET=legacy`, d'enregistrer l'oracle, puis de l'exécuter avec `TARGET=app`. Ici, le scénario ne peut tout simplement pas tourner contre `legacy`.
2. **Tag `@legacy` mensonger.** Le test est taggé `@legacy`, mais il n'y a aucun mécanisme pour le rejouer contre Wallos.
3. **Échantillon réduit.** Même contre `TargetDriver`, seuls 3 des 7 vecteurs de l'oracle sont exercés (`year:1:120.00`, `week:1:10.00`, `month:3:15.00`). Les cas `day`, `month:1`, `year:99.99`, `week:2` ne sont pas couverts en e2e.

### Recommandation

- Ajouter `subscriptionYearlyCost(name: string): Promise<string>` à `AppDriver`.
- Implémenter cette méthode dans `LegacyDriver` (scrutation du DOM Wallos réel).
- Réécrire le test pour accepter une injection de driver (`{ app }: { app: AppDriver }`).
- Exécuter le scénario avec `TARGET=legacy` pour valider l'oracle, puis avec `TARGET=app`.
- Étendre l'échantillon e2e à l'ensemble des vecteurs, ou au moins aux cas significativement différents (`day`, `year:99.99`).

## F2 — `row_to_dto` retombe sur zéro pour un montant négatif

### Description

Dans le commit ciblé :

```rust
// crates/server/src/subscriptions.rs:239-253 (commit 903d871)
let (monthly, yearly) = match (CurrencyCode::new(&row.currency), cycle) {
    (Ok(currency), Some(cycle)) => {
        let price = Money::new(row.amount, currency).unwrap_or_else(|_| Money::zero(currency));
        (
            wallos_core::stats::monthly_cost_rounded(price, cycle)
                .amount()
                .to_string(),
            wallos_core::stats::yearly_cost_rounded(price, cycle)
                .amount()
                .to_string(),
        )
    }
    _ => (row.amount.to_string(), row.amount.to_string()),
};
```

Le commentaire dit : « Une ligne à la devise ou au cycle illisible retombe sur le montant brut (jamais un zéro silencieux). »

En réalité, si la devise et le cycle sont valides mais que `row.amount < 0`, `Money::new` échoue et on expose `"0"` pour `monthly_cost` **et** `yearly_cost` — un zéro silencieux — au lieu du montant brut.

### Conséquences

- **Mauvaise dégradation.** Une ligne corrompue masquerait son montant réel dans les champs dérivés, ce qui fausserait les totaux affichés et compliquerait le diagnostic.
- **Incohérence avec la branche `_`** qui expose bien `row.amount.to_string()`.

### Recommandation

Traiter `Money::new(row.amount, currency).is_err()` comme la branche `_` : exposer `row.amount.to_string()` pour `monthly_cost` et `yearly_cost`.

## F3 — L'oracle sous-représente les cas limites

### Description

L'oracle ne contient que des cas EUR à 2 décimales, avec des valeurs qui tombent juste après arrondi. Il ne couvre pas :

- **JPY** (0 décimales) : `yearly_cost_rounded` doit arrondir à l'unité.
- **Achat one-time** (`cycle = 5` dans Wallos, non supporté encore dans `BillingUnit`) : `getPricePerMonth` retourne 0, donc l'annuel attendu est 0.
- **Arrondi half-to-even** : un prix hebdomadaire ou quotidien dont `yearly_cost` brut tombe exactement sur un demi (ex. `0.005`) pour vérifier la stratégie d'arrondi.

### Conséquences

- L'e2e et les tests unitaires ne valident pas que `yearly_cost_rounded` respecte le nombre de décimales de la devise.
- L'absence de one-time laisse une ambiguïté sur le comportement attendu quand ce cycle sera ajouté.

### Recommandation

Ajouter des vecteurs pour JPY et un vecteur à la frontière d'arrondi. Documenter le cas one-time dès que `BillingUnit::OneTime` est introduit.
