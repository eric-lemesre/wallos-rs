## Traitement (consigne : traiter + annoter)

Corrections appliquées dans la **PR CAT-004** (mêmes fichiers proto/migrations/tests).

| # | Sévérité | Finding | Statut | Décision |
|---|----------|---------|--------|----------|
| 1 | HIGH | `end_date < first_payment` accepté (période de facturation vide, échéance impossible) sans validation ni `CHECK` | ✅ **CORRIGÉ** | Validation `end_date >= first_payment` dans `CreateSubscriptionRequest::into_core` (422 champ `end_date`) **et** `SubscriptionDto::into_core` (`DomainError`) + migration `0015` `CHECK (end_date IS NULL OR end_date >= first_payment)`. |
| 2 | MEDIUM | `422 "first_payment: échéance hors plage"` trompeur quand `end_date < first_payment` mais pas encore terminé | ✅ **CORRIGÉ** | Même correctif : la validation en amont renvoie une erreur claire sur `end_date` avant le calcul d'échéance. |
| 3 | MEDIUM | Cas `end_date == today` non testé (frontière la plus risquée pour les agrégats) | ✅ **COUVERT** | Test core `has_ended_after_end_date` : `has_ended(end) == false` (le jour même n'est pas terminé), `has_ended(end+1) == true`. |

1 déjà couvert (frontière `end == today`). Aucun défaut d'isolation ni de recalcul d'échéance.
